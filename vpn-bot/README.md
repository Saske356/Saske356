# 🛡 Aurora VPN: бот для продажи подписки

Telegram-бот, который продаёт доступ к VPN за **Telegram Stars**. Карта, банк и платёжный провайдер не нужны: оплата идёт внутри Telegram.

> Без сервера бот работает в **демо-режиме** и выдаёт ключи с пометкой DEMO, а весь путь покупки при этом работает по-настоящему. Настоящий VPN ставится на сервер одной командой, см. «Установка на сервер».

## Что умеет
- 🚀 **Тарифы** на 1, 3, 6 и 12 месяцев со скидками, оплата звёздами прямо в чате.
- 📱 **Устройства**: при покупке гость выбирает 1, 2, 3 или 5 устройств, цена растёт по множителю (`DEVICE_OPTIONS` в `config.py`).
- 🗝 **Мои подписки**: у одного гостя может быть несколько подписок, у каждой свой ключ, срок и название, которое можно поменять.
- 🔁 **Автопродление** для тарифа на месяц: встроенные подписки Telegram Stars, звёзды списываются сами раз в 30 дней. Отключается кнопкой в боте или в настройках Telegram.
- 🎀 **Подарки**: гость оплачивает подписку для друга и получает ссылку, по которой подарок активируется в один шаг.
- 🎁 **Пробный период** (по умолчанию 1 день, один раз на человека).
- 👥 **Рефералка**: +3 дня за каждого нового друга, который запустил бота по ссылке. Можно переключить на «бонус после оплаты друга» (`REF_ON_JOIN=0`).
- 📣 **Бонус за подписку на канал**: +1 день один раз. Задаётся через `CHANNEL`, бот должен быть админом канала, чтобы проверять подписку.
- 🛎 **Консьерж в боте**: гость пишет вопрос, тебе приходит тикет, ты отвечаешь ответом на сообщение, и бот пересылает ответ гостю.
- 🎟 **Промокоды** с ограничением по числу активаций.
- ⏳ **Напоминание** за сутки до конца подписки (кроме подписок с автопродлением) и автоматическое отключение после.
- 🛠 **Админка**: статистика и выручка, рассылка, выдача дней, промокоды, платежи с возвратом в одну кнопку.
- 📄 Команды `/terms` и `/paysupport`, которые Telegram требует от ботов с оплатой.

Лимит устройств пока не проверяется на сервере: гость получает подписку на выбранное число устройств, но физически ключ можно вставить и на больше. Проверку подключений добавим, когда VPN будет работать на настоящем сервере.

## Запуск
1. Создай бота у **@BotFather** (`/newbot`) и получи токен.
2. Узнай свой Telegram ID у **@userinfobot**: он нужен для админки.
3. Скопируй `.env.example` в `.env` и заполни. Токен пиши **только в этот файл**: никому его не отправляй и не выкладывай на GitHub (файл `.env` уже в `.gitignore`).
4. Установи и запусти:

```bash
pip install -r requirements.txt
python bot.py
```

Для постоянной работы бота держи его на том же VPS, где будет VPN. Для теста подойдёт и Termux на Android (`pkg install python python-pillow`, затем шаги выше).

## Настройка
| Что | Где |
|---|---|
| Название, слоган, поддержка, пробный период, бонус за друга | `.env` |
| Цены и сроки тарифов, список преимуществ | `config.py` → `PLANS`, `FEATURES` |
| Баннеры разделов и аватарка | папка `banners/`, пересоздаются командой `python make_banner.py` после смены названия |

В `FEATURES` пиши только правду про свой сервер: скорость, страны и так далее.

## Оформление
- Чёрно-золотой стиль: у каждого раздела свой баннер, а после оплаты появляется экран «Добро пожаловать» с конфетти.
- При запуске бот сам ставит себе имя (`BRAND`), описание, которое видно до /start, и меню команд. Отключить это можно через `SET_PROFILE=0`.
- Аватарку бот поставить себе не может: возьми `banners/avatar.jpg` и загрузи её в @BotFather командой `/setuserpic`.

## Мини-приложение
В папке `docs/` лежит мини-приложение: оно открывается прямо внутри Telegram. В нём статус подписки, тарифы с оплатой, ключ с QR-кодом, инструкции и приглашение друзей.

1. Включи GitHub Pages: репозиторий → **Settings → Pages** → Source: **Deploy from a branch** → ветка с ботом, папка **/docs** → **Save**.
2. Через пару минут приложение откроется по адресу `https://<ник>.github.io/<репозиторий>/`.
3. Впиши этот адрес в `.env`: `MINIAPP_URL=https://...` и перезапусти бота.

Бот сам создаёт ссылки на оплату и ставит каждому пользователю кнопку «Приложение» в меню чата с его данными. Отдельный сервер для приложения не нужен.

## Команды админа
- `/admin`: статистика, выручка и рассылка
- `/give <id> <дней>`: начислить дни пользователю
- `/addpromo <КОД> <дней> <активаций>`: создать промокод
- `/payments [id или @ник]`: список платежей с кнопкой возврата у каждого
- `/refund <charge_id>`: вернуть звёзды по charge_id
- `/testpay`: тестовая оплата на 5 ⭐, чтобы проверить оплату и возврат
- `/server`: состояние сервера без SSH: работает ли VPN и раздача подписок, последняя ошибка, нагрузка, память, диск
- `/backup`: прислать резервную копию базы и настроек VPN

Если VPN не смог применить настройки (Xray отклонил конфиг или не перезапустился), бот сразу пишет админам «⚠️ Проблема с VPN» с текстом ошибки. Прежний рабочий конфиг при этом остаётся.

## Hysteria для стран через прокси
Каждая страна, добавленная через `/addloc` или найденная авто-прокси, получает свой сервер Hysteria на отдельном UDP-порту из диапазона `30000-30049` (`HY2_LOC_PORTS`). Трафик из него выходит через прокси этой страны. В подписке у такой страны появляется пункт «Страна · Hysteria», а при включённом Xray рядом остаётся и подключение по TCP.

- Бот сам пишет конфиг и запускает службу `aurora-hy2@loc-КОД`. При изменении стран перезапускается только сервер изменившейся страны; основная Hysteria и остальные страны не трогаются.
- Авто-страны идут через ретранслятор, поэтому замена умершего прокси ничего не перезапускает.
- Пароль у гостя один на все страны; трафик, лимит устройств и отключение работают на всех серверах.
- Порт каждой страны виден в `/locations`. У хостинга нужно открыть **UDP 30000–30049**: установщик открывает их только в `ufw`.
- Через купленный SOCKS5 идёт и UDP. Через HTTP-прокси и бесплатные прокси — только TCP: запросы DNS уходят с сервера, остальной UDP отклоняется.

В подписке одна Hysteria на страну. Второй вариант с обфускацией (отдельный порт, пакеты похожи на случайные данные) выключен: включить — `HY2_OBFS_ON=1` в `.env` и запустить установщик ещё раз.

## Купленные прокси списком (Webshare)
Если прокси куплены пачкой, их не нужно добавлять по одному. В Webshare: **Proxy List → Download**, скопировать ссылку на скачивание и отправить боту:

```
/webshare https://proxy.webshare.io/api/v2/proxy/list/download/...
```

- Ссылка хранится только на сервере, сообщение с ней бот сразу удаляет из чата.
- Бот скачивает список, проверяет каждый прокси настоящим HTTPS-запросом и определяет страну по тому, откуда прокси выходит в интернет. В каждой стране остаётся самый быстрый и два запасных, стран не больше 20 (`WEBSHARE_MAX`).
- Раз в 10 минут бот проверяет рабочий прокси и, если он умер, сразу берёт живой запасной. Раз в 3 часа список скачивается заново: появляются новые страны, исчезнувшие убираются.
- У каждой такой страны есть Hysteria (свой UDP-порт) и TCP. Авто-страна с тем же кодом уступает место купленной, а страны, добавленные через `/addloc`, бот не трогает.
- `/webshare` — состояние, `/webshare now` — проверить сейчас, `/webshare off` — убрать эти страны и забыть ссылку.
- Подходит любой сервис, который отдаёт список по ссылке в виде `host:port:логин:пароль`, `логин:пароль@host:port` или `socks5://…`.

## Готовые конфиги для Happ и v2rayNG
Happ и v2rayNG получают не ссылки, а готовый JSON-конфиг на каждую страну. В приложении видно только название — «🇵🇱 Польша», а адрес сервера и пароль лежат внутри конфига, как у крупных сервисов. В конфиге:
- российские сайты (.ru, .рф, Яндекс, VK, банки) идут напрямую, мимо VPN: Госуслуги и банки не видят зарубежный IP, пинг до них минимальный;
- DNS через HTTPS: российские домены — через Яндекс, остальные — через Cloudflare и Google;
- реклама отсекается;
- Hysteria описан встроенным в Xray протоколом, сертификат сверяется по отпечатку.

Первым в списке идёт **«🚀 Лучший сервер»**: в нём собраны все страны и способы подключения, приложение раз в минуту замеряет каждый и ведёт трафик через самый быстрый из живых. Если какой-то способ перестал проходить (например, оператор режет TCP), он выпадает сам. Поэтому Xray (`XRAY=1`) можно держать включённым вместе с Hysteria: где Reality проходит, «Лучший сервер» возьмёт его, где нет — Hysteria.

Нужна свежая версия приложения: Hysteria внутри Xray появилась недавно. Если конфиги не открываются, кнопка «🧩 Happ/v2rayNG» в `/admin` возвращает обычные ссылки всем, а `?format=links` в конце адреса подписки — одному гостю. Hiddify и другие приложения всегда получают ссылки.

## Только Hysteria и смена сайта маскировки
Если оператор режет TCP, Xray можно выключить: `XRAY=0` при запуске установщика. Тогда в подписке только Hysteria, и у стран нет приписок: просто «🇵🇱 Польша», «🇩🇪 Германия». Вернуть Xray: `XRAY=1`.

Hysteria выдаёт себя за обращение к обычному сайту, и это имя видно оператору. Раз в сутки бот меняет его на другой сайт из своего списка, который отвечает с сервера (`HY2_SNI_EVERY=24`, `/sni every 24`, `/sni every off`). Сервер Hysteria принимает любое имя, поэтому ничего не перезапускается, прежние ссылки продолжают работать, а приложения заберут новую подписку сами. Гостям сообщений не приходит, о смене узнают только админы. Без Xray `/sni` управляет сайтом Hysteria: `/sni` — состояние, `/sni next` — сменить сейчас.

## Лимит устройств и трафик
Раз в 5 минут бот спрашивает у Hysteria, сколько подключений у каждой подписки, а у Xray — с каких адресов подключены её ключи. Раз в 10 минут забирает трафик.

- Устройств больше, чем оплачено, две проверки подряд — гость получает предупреждение. Если превышение продолжается ещё три проверки, подписка отключается на 30 минут и потом включается сама. Админам приходит сообщение.
- Одна случайная лишняя запись (телефон сменил Wi-Fi на мобильную сеть) ни к чему не приводит.
- Трафик виден гостю в подписке, в приложении VPN и админу в `/traffic`: кто больше всех тратит, сколько устройств онлайн.
- Настройки: `DEVICE_LIMIT=block` (по умолчанию), `warn` — только предупреждать, `off` — не проверять; `DEVICE_BLOCK_MINUTES`.

## Скидки и возврат гостей
- За 3 часа до конца пробного периода бот напоминает о нём с кнопками тарифов (`TRIAL_REMIND_HOURS`).
- Не купил — после конца пробного получает скидку 15% на первую покупку на 72 часа (`TRIAL_OFFER`, `OFFER_HOURS`).
- Через 3 и 7 дней после окончания всех подписок — персональная скидка 20% и 30% (`WINBACK=3:20,7:30`, пусто — выключено). Каждое предложение приходит один раз; тем, кто ушёл больше 30 дней назад, бот не пишет.
- Скидка действует только на разовую оплату и сгорает после неё. Воронка продаж — в `/funnel`.
- Рассылка из `/admin` идёт в фоне: бот в это время отвечает гостям, а если Telegram просит подождать, отправляет сообщение повторно.

## Резервные копии
Кроме Telegram копия сохраняется на диске сервера (`backups/` рядом с базой, последние 7). С `BACKUP_PASSWORD` в `.env` она шифруется AES-256 и приходит одним архивом; расшифровать: `openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in ФАЙЛ.tar.gz.enc | tar xz`. С `BACKUP_RCLONE=yadisk:aurora` копия уходит ещё и в облако (сначала `rclone config` на сервере).

Раз в сутки бот присылает админам два файла: `bot.db` (гости, подписки, платежи) и `vpn.json` (секрет ключей, страны, мосты). Отключить: `BACKUP_DAILY=0`. Храни их у себя и никому не пересылай.

Как восстановить на новом или сброшенном сервере:
1. Запусти установщик и ответь на вопросы как обычно.
2. Останови бота: `systemctl stop aurora-bot`.
3. Положи файлы из копии на место (например, через SFTP в Termius): `bot.db` → `/opt/aurora/vpn-bot/bot.db`, `vpn.json` → `/var/lib/aurora/vpn.json`.
4. Запусти бота: `systemctl start aurora-bot`.

Подписки и сроки вернутся. Ключи Reality на новом сервере другие, поэтому клиентам достаточно обновить подписку в приложении, а если сменился IP сервера, заново скопировать ссылку из бота.

## Установка на сервер
Нужен VPS на Ubuntu 22.04/24.04 или Debian с выделенным IPv4. Зайди на него по SSH (с Android подойдёт Termux: `pkg install openssh`, затем `ssh root@IP`) и выполни:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/claude/android-usage-ql87m8/vpn-bot/install.sh)
```

Установщик сам поставит Xray (VLESS Reality на порту 443), бота, раздачу подписок (порт 2096), включит BBR и автозапуск. Он спросит токен бота, твой Telegram ID и название страны сервера. Настройки останутся только на сервере, в `/opt/aurora/vpn-bot/.env`. Повторный запуск той же команды обновляет бота и сохраняет настройки.

Если в конце что-то не запустилось, установщик покажет две команды: их вывод пригодится, чтобы найти причину.

## Несколько стран на одном сервере
Клиенты всегда подключаются к твоему серверу, а сервер выпускает трафик либо напрямую, либо через прокси другой страны. Сайты видят IP этой страны.

1. Купи недорогие серверные IPv4-прокси (SOCKS5 или HTTP) в нужных странах. Проверь, что продавец разрешает такое использование.
2. Добавь страну командой в боте:
   `/addloc nl 🇳🇱 Нидерланды | socks5://логин:пароль@ip:порт`
3. Список стран: `/locations`, удаление: `/delloc nl`.

Каждый клиент получает **одну ссылку-подписку**. В Hiddify, v2rayNG или Streisand она превращается в список стран и показывает дату окончания доступа. Новые страны появляются у клиентов сами при обновлении подписки.

Перед каждым применением бот проверяет конфиг самим Xray и при ошибке оставляет прежний рабочий.

**Только Hysteria, без Xray.** При установке бот спрашивает, оставить ли Xray. По умолчанию остаётся только Hysteria (`XRAY_ENABLED=0` в `.env`): в подписке два пункта, «· Hysteria» и «· Hysteria 2», Xray остановлен. Страны через прокси и авто-страны в этом режиме не работают: они идут через Xray. Вернуть Xray: `XRAY_ENABLED=1` в `.env` и снова запустить установщик.

**Подписка на своём домене.** Ссылка вида `https://sub.example.com/ZKwXhAPWFBHb7NZn`: 16 случайных букв и цифр, по ним нельзя угадать чужую подписку. Как включить:
1. Купи домен (или возьми поддомен своего) и у регистратора добавь запись A на IP сервера. Если домен в Cloudflare, облако должно быть серым (без проксирования).
2. Запусти установщик: он спросит домен, сам получит сертификат Let's Encrypt (нужен открытый порт 80) и настроит его продление.
3. Бот раздаёт подписку по HTTPS на порту 443 (если Xray выключен) или 2053 (если Xray включён, тогда в ссылке будет `:2053`). Новые ссылки клиенты видят в боте, старые ссылки вида `http://IP:2096/sub/...` продолжают работать.

**Hysteria2 по UDP.** Установщик ставит рядом с Xray сервер Hysteria2 в двух вариантах: обычный на 443/udp (похож на HTTP/3) и с обфускацией на 8443/udp (похож на случайный UDP). В подписке они идут первыми: «· Hysteria» и «· Hysteria 2». Когда оператор режет TCP-подключения к зарубежным серверам и у Xray пропадает пинг, UDP часто проходит. Пароли клиентов Hysteria проверяет у бота при каждом подключении, поэтому выдача и отключение доступа её не перезапускают, а при отключении открытые сессии обрываются сразу. Если у хостинга есть свой файрвол, открой в нём 443/udp и 8443/udp. Состояние видно в `/server`, проверка — в `diag.sh`. Hysteria работает только для основной страны и мостов «ru» (мост пересылает и UDP 443).

**Без перезапусков.** Выдача, продление и отключение доступа идут через API Xray на лету: подключения остальных клиентов не рвутся. Xray перезапускается только при смене стран, мостов или сайта маскировки. Если API не ответил (например, Xray упал), бот просто перезапускает Xray с новым конфигом. Сколько было перезапусков и изменений на лету, видно в `/server`.

**Запасное подключение.** На том же порту 443 работает второй вид подключения, VLESS XHTTP Reality. В подписке у основной страны, купленных стран и мостов появляется пункт с пометкой «· запасной». Если обычное подключение у оператора работает с перебоями, клиенту достаточно выбрать запасной. Отключить: `XHTTP=0` в `.env`. Если Xray слишком старый и не принимает XHTTP, бот работает без него и пишет админу.

**Если оператор режет подписку.** В экране подписки есть кнопка «🔑 Ключи без подписки»: бот присылает ключи прямо в чат. Можно раздавать подписку и через свой домен, например за Cloudflare: укажи `SUB_URL=https://sub.example.com` в `.env`, и ссылки клиентов будут вести туда (домен должен пересылать запросы на порт подписки сервера).

Каждые 10 минут бот проверяет прокси стран, добавленных вручную: открывает через каждый настоящее HTTPS-подключение. Так ловится не только выключенный прокси, но и истёкший логин. Если прокси не работает, страна скрывается из подписки, а тебе приходит сообщение. Когда прокси оживает, страна возвращается сама.

## Авто-страны из публичных прокси
Бот умеет сам брать бесплатные прокси из открытых списков, добавлять из них страны и менять прокси, когда он перестаёт отвечать. Включается командой `/autoproxy on`, по умолчанию выключено.

> ⚠️ Публичные прокси медленные и живут от минут до часов. Их владельцы видят, к каким адресам идут подключения клиентов (содержимое HTTPS-сайтов остаётся зашифрованным). Это бесплатное дополнение, а не замена купленным прокси: для платящих клиентов надёжнее раздел выше.

Как это устроено:
- **Списки.** Прокси берутся из открытых источников (proxifly, proxyscrape, geonode, monosans). Если один недоступен, работают остальные.
- **Скорость.** Каждый новый прокси проходит замер: через него скачивается 256 КБ. Медленнее 80 КБ/с и с задержкой больше 3,5 с не берём: через такие прокси VPN работает с перебоями. Скорость видна в `/autoproxy`.
- **Репутация.** Бот помнит, какие прокси проходили проверки, а какие подводили. Подводившие пробуются последними, так что со временем страны держатся на самых стабильных. Если запасной прокси заметно быстрее рабочего, он становится рабочим.
- **Без зависаний.** Если рабочий прокси не ответил за 1,5 секунды, ретранслятор параллельно пробует запасной и берёт того, кто ответил первым.
- **Проверка.** Через каждый прокси бот открывает настоящее HTTPS-подключение и проверяет сертификат сайта. Прокси, который не умеет пересылать HTTPS или подменяет шифрование, отбрасывается. Страна определяется по тому, откуда прокси на самом деле выходит в интернет, а не по записи в списке. Прокси, которые пускают только на порт 443, тоже отбрасываются: через них не работают обычные сайты и часть приложений.
- **Без спешки.** За одну проверку бот пробует не больше 60 новых прокси, начиная с тех, у кого лучше история в списках. Сотни подключений к чужим адресам подряд хостинг может принять за сканирование сети, поэтому первые страны появляются за несколько минут, а полный набор собирается постепенно.
- **Запасные.** У каждой страны есть рабочий прокси и до двух запасных. Если рабочий не ответил, это же подключение сразу уходит через запасной.
- **Без перезапуска VPN.** Xray подключается не к публичному прокси, а к ретранслятору внутри бота (`127.0.0.1:20808`), и тот сам выбирает живой прокси. Поэтому замена прокси не перезапускает Xray и не рвёт подключения остальных клиентов. Xray перезапускается, только когда меняется набор стран, и не чаще одного раза за проверку.
- **Перепроверка.** Раз в 5 минут бот проверяет все прокси авто-стран, убирает умершие и добирает новые. Если живых прокси для страны нет, она прячется из подписки и возвращается, когда прокси найдётся. При подборе страна, которая не вернулась за 6 часов, уступает место другой.
- **Защита от ложной тревоги.** Если проверочный сайт недоступен с самого сервера, бот пропускает проверку и ничего не меняет.
- **Защита основного VPN.** Если Xray не принимает конфиг с авто-странами, бот применяет конфиг без них и пишет тебе причину. Основная страна, купленные прокси и новые клиенты от авто-стран не зависят.

Команды:
- `/autoproxy`: состояние, текущие прокси, их скорость и число замен
- `/autoproxy on`: включить, бот сразу начнёт искать прокси
- `/autoproxy off`: выключить и убрать авто-страны
- `/autoproxy now`: проверить и обновить сейчас, результат придёт сообщением
- `/autoproxy test`: проверить каждую страну так, как подключается клиент, и состояние Xray
- `/autoproxy countries nl de us`: держать именно эти страны (коды из двух букв)
- `/autoproxy countries auto`: бот подбирает страны сам, начиная с популярных
- `/autoproxy max 8`: сколько стран держать при подборе
- `/autoproxy notify off`: не присылать сообщения о заменах

В `/locations` авто-страны помечены значком 🤖. Страны, добавленные через `/addloc`, бот не трогает. Если убрать авто-страну через `/delloc`, бот больше не добавит её сам; вернуть её можно командой `/autoproxy include nl`.

Через авто-страны идёт только TCP: публичные прокси не пересылают UDP. Запросы DNS клиентов этих стран сервер отправляет сам, остальной UDP отклоняется, и приложения переходят на обычное подключение.

Стартовые значения можно задать в `.env` (`AUTO_PROXY`, `AUTO_PROXY_COUNTRIES`, `AUTO_PROXY_MAX`). Они читаются только при первом запуске, дальше настройки меняются командами. Порт ретранслятора задаётся через `AUTO_RELAY_PORT`.

Проверка без сервера: `python3 -m unittest discover -s tests` поднимает на своём компьютере тестовые прокси и проверяет поиск, замену и ретранслятор.

## Сайт маскировки
VPN выдаёт подключение за обращение к обычному сайту (Reality). Имя этого сайта видно оператору в первом пакете, поэтому неудачный выбор приводит к обрывам. Сайтом управляет команда `/sni` в боте:

- `/sni`: какой сайт сейчас и какие настройки
- `/sni next`: подобрать и поставить другой сайт сейчас
- `/sni list`: какие сайты подходят с этого сервера
- `/sni www.example.com`: поставить конкретный сайт
- `/sni every 24`: менять сайт каждые 24 часа, `/sni every off`: не менять по расписанию
- `/sni auto off`: не менять сайт при сбое

Раз в 10 минут бот проверяет, что сайт отвечает с сервера по TLS 1.3 и HTTP/2. Если сайт три раза подряд не ответил, бот сам ставит другой и пишет админам. Смена по расписанию выключена, пока её не включить: сама по себе она от блокировки не спасает, а клиентам после каждой смены нужна обновлённая подписка.

В списке бота нет Microsoft, Apple и других самых известных сайтов: их адреса наперечёт, чужой сервер под таким именем заметен сразу, и Xray сам предупреждает, что это повышает риск блокировки. Поставить такой сайт вручную можно, бот покажет предупреждение.

После смены приложения получают новые ключи при обновлении подписки, сами они делают это раз в час. Если новый сайт отвечает и на чужое имя, ключи с прежним сайтом принимаются ещё сутки.

## Обход белых списков (мосты)
Когда мобильный интернет переходит на белые списки, зарубежные серверы недоступны, а российские обычно остаются. Мост — это недорогой российский сервер, который пересылает подключения на основной:

клиент → мост в России → основной сервер → интернет

При белых списках оператор пропускает только адреса и сайты из списка. Поэтому важны две вещи: IP моста должен быть из сети, которую оператор пропускает, а подключение к мосту должно выглядеть как обращение к российскому сайту из списка. Второе бот делает сам.

1. Сначала обнови основной сервер установщиком этой версии: на нём появится отдельный вход для мостов (порт 8444, задаётся `BRIDGE_PORT`). Если у хостинга есть свой файрвол, открой в нём порт 8444.
2. Возьми дешёвый VPS в России с Ubuntu или Debian. При белых списках чаще остаются доступны сети крупных российских облаков (Яндекс Облако, VK Cloud, Selectel и подобные), но это зависит от региона и оператора. Проверь мост на своём операторе: включи мобильный интернет и подключись.
3. Зайди на него по SSH и запусти установщик в режиме моста:
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/claude/claude-md-review-rqdps8/vpn-bot/install.sh) bridge
   ```
   Он спросит IP основного сервера, проверит, что тот отвечает, и в конце покажет команду для бота. Если на основном сервере Xray выключен (только Hysteria), предупреждение про порт 8444 — это нормально: мост пересылает Hysteria по UDP 443.
4. В боте: `/addbridge ru1 🇷🇺 Обход | IP_МОСТА | ru`. Бот сам подберёт российский сайт для маскировки (Госуслуги, VK, Яндекс, Дзен и другие: берётся первый, который отвечает с сервера). У всех клиентов в подписке появятся пункты «🇷🇺 Обход» и «🇷🇺 Обход · запасной».

Как это устроено: клиент подключается к мосту в России, а Reality отвечает от имени российского сайта. Кто проверит мост без ключа, увидит настоящий российский сайт с его сертификатом. Мост пересылает и Hysteria (UDP 443 и порты стран 30000–30049), поэтому через него работают все страны: «🇩🇪 Германия · 🇷🇺 Обход». Мост просто пересылает трафик на основной сервер и ничего не хранит: пользователей, ключи и оплату ведёт основной сервер.

- `/bridgesite`: какой сайт сейчас, `/bridgesite next`: подобрать другой, `/bridgesite vk.com`: поставить этот.
- Раз в 10 минут бот проверяет, что сайт моста отвечает, и при сбое ставит другой. Там же он проверяет каждый мост и пишет, если мост перестал отвечать.

Мосты, поставленные прежним установщиком, продолжают работать как раньше (без `| ru`). Третьим полем у них можно указать сайт: `| vk.com`. Чтобы старый мост проходил белые списки, запусти на нём установщик моста этой версии и добавь его заново с `| ru`.

Своя страна для своего движка: в `vpn.py` можно подключить любой другой класс с методами `issue()` и `revoke()`.

## Диагностика и тесты
Если клиенты не могут подключиться, запусти на сервере диагностику. Она ничего не меняет, не печатает токен и ключи, сама подключается к VPN так же, как клиент, и говорит, где проблема: в настройке сервера или по дороге к нему.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/claude/android-usage-ql87m8/vpn-bot/diag.sh)
```

Диагностика проверяет и запасное подключение XHTTP, и вход для мостов.

Если сервер исправен, а телефон не подключается, запусти её с параметром `watch` и за минуту нажми в приложении проверку пинга или подключись. Она покажет, на каком шаге обрывается подключение телефона: не доходит до порта, обрывается по дороге, отклоняется сервером или принимается. На эту минуту включается подробный журнал Xray (он дважды перезапускается), потом настройки возвращаются как были.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/claude/android-usage-ql87m8/vpn-bot/diag.sh) watch
```

Если наблюдение показало, что связь с сервером устанавливается, но данные от телефона не приходят, оператор распознаёт подключение по первому пакету, в котором виден сайт маскировки. Смени его одной командой:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/claude/android-usage-ql87m8/vpn-bot/sni.sh)
```

Она проверяет с сервера список сайтов (TLS 1.3, HTTP/2, настоящий сертификат), пропускает те, о которых предупреждает сам Xray, переключает сервер и делает пробное подключение. Если VPN с новым сайтом не заработал, прежний сайт возвращается сам. После смены клиентам нужно обновить подписку в приложении. С параметром `list` команда только показывает подходящие сайты, а с именем сайта ставит именно его.

Перед любым изменением кода прогоняй общий набор тестов из папки бота:

```bash
python3 -m unittest discover -s tests
```

В нём сценарии бота от /start до возврата (`test_bot_flows.py`), модуль VPN и установщик (`test_xray_core.py`) и авто-страны (`test_auto_proxy.py`). В сеть и в Telegram тесты не ходят. Для сценариев бота нужны его библиотеки (`pip install -r requirements.txt`), без них этот тест пропускается.

## Своё приложение Aurora VPN для Android
Папка `android/` собирает из v2rayNG (GPL-3.0) приложение со своим названием, иконкой и настройками.
Сборку делает GitHub Actions (`.github/workflows/android.yml`) при каждом изменении в `android/`,
готовые APK лежат в Releases репозитория.

- В боте: «📲 Подключение» → Android → «📥 Скачать приложение» (или команда `/app`). Бот берёт свежий APK
  из Releases и присылает файлом. В карточке подписки кнопка «⚡ Открыть в приложении» добавляет подписку одним касанием.
- Подписка для обычного Happ, v2rayNG и остальных не меняется.
- Своему приложению бот отдаёт конфиги с keepalive для Hysteria (`client_config.AURORA_QUIC`):
  соединение не засыпает, страницы после паузы открываются без нового рукопожатия.
- В приложении по умолчанию: пинг меряется по HTTP (без лишнего TLS), после обновления подписки
  серверы сами проверяются и сортируются, «Лучший сервер» перепроверяется раз в минуту, рекламы нет.
- `APP_REPO=` (пусто) в `.env` — убрать кнопки приложения.
- Подпись APK: ключ `android/aurora.keystore` лежит в открытом репозитории. Чтобы подписывать своим секретным
  ключом, добавьте в секреты репозитория `AURORA_KEYSTORE_BASE64`, `AURORA_KEYSTORE_PASSWORD`, `AURORA_KEY_ALIAS`,
  `AURORA_KEY_PASSWORD` (после смены ключа приложение придётся один раз переустановить).

## Автообновление сервера
После установки сервер сам проверяет ветку на GitHub каждые 10 минут (таймер `aurora-update.timer`) и, если там новый код,
запускает установщик без вопросов (`AURORA_AUTO=1`). Бот после обновления пишет админам, на что обновился.
- `/update` в боте — проверить и обновить сразу.
- Ветка запоминается в `.env` как `AURORA_BRANCH`, `AUTO_UPDATE=0` — выключить.
- Журнал: `journalctl -u aurora-update -n 50`.
