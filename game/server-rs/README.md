# Сервер Новоград RP на Rust

Полная замена `server.js`: тот же протокол, тот же `data/players.json` и те же пароли (scrypt
с параметрами Node.js), поэтому игроки и лаунчер переходят на него без изменений. Город генерируется
тем же алгоритмом, что и у клиента (общая библиотека `world-rs`), — здания, деревья и адреса доставки совпадают
с JS бит в бит (`--dump-world` выводит город для проверки).

## Сборка и запуск

```bash
cd game
npm install                 # клиент использует three.js из node_modules
npm run build:rust          # = cargo build --release -p novograd-server
npm run start:rust          # http://localhost:3000
```

Переменные окружения те же, что у Node-сервера: `PORT`, `DATA_DIR`, `SERVER_NAME`, `SERVER_COLOR`,
`MAX_PLAYERS`, плюс `GAME_DIR` — папка игры (по умолчанию текущая или родительская).
Готовый бинарник `game/target/release/novograd-server` один, ~2 МБ, без зависимостей — его можно скопировать на VPS и запустить.

### systemd

```ini
[Unit]
Description=Novograd RP
After=network.target

[Service]
WorkingDirectory=/opt/novograd/game
Environment=PORT=3000 SERVER_NAME=Новоград\x20#1 MAX_PLAYERS=500
ExecStart=/opt/novograd/game/target/release/novograd-server
Restart=always

[Install]
WantedBy=multi-user.target
```

## Что оптимизировано

- **Зона видимости.** Каждый игрок получает только тех, кто в радиусе 150 м (сетка по городу + проверка расстояния),
  а не весь сервер.
- **Без повторов.** Ник и неизменные данные машин (модель, цвет, владелец, номер) уходят игроку один раз — при первом
  появлении; дальше 15 раз в секунду только координаты.
- **Сборка снимков на всех ядрах** при 200+ игроках.
- **Пачки сообщений.** Всё, что накопилось для игрока, уходит одним системным вызовом; медленному клиенту лишнее
  не копится (очередь 256, снимки выбрасываются, а ники переотправляются).
- **Вход не тормозит игру.** scrypt считается в фоновых потоках (не больше числа ядер одновременно),
  у Node.js каждый вход замораживал весь сервер примерно на 30 мс.
- Маленькие буферы WebSocket, распределитель памяти mimalloc.

## Замеры

`node tools/bench.mjs <порт> <pid> <ботов>` — боты входят и бегают по городу, 15 обновлений/с.
4 ядра, боты и сервер на одной машине:

| | Node.js, 300 | **Rust, 300** | Node.js, 1000 | **Rust, 1000** |
|---|---|---|---|---|
| Трафик на игрока | 210 КБ/с | **20 КБ/с** | 708 КБ/с | **67 КБ/с** |
| Трафик сервера всего | 62 МБ/с | **6 МБ/с** | 691 МБ/с | **65 МБ/с** |
| CPU (доля одного ядра) | 8.6% | **7.7%** | 35% | **29%** |
| Память | 93 МБ | **26 МБ** | 112 МБ | 126 МБ |
| Вход всех ботов | 8.5 с | **2.5 с** | 29.5 с | **9.2 с** |

Главный выигрыш — сеть: при 1000 игроках Node-серверу нужен канал ~5,5 Гбит/с, Rust — ~0,5 Гбит/с,
а мобильному игроку ~0,5 Мбит/с вместо 5,7 Мбит/с.
