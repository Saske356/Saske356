# Saske Messenger

Защищённый веб-мессенджер (в духе Telegram / WhatsApp), работающий как
артефакт на claude.ai.

**Приложение:** https://claude.ai/artifact/LdNrnzQBwAvck1FbFGG7QQ

## Возможности

- Личные и групповые чаты, поиск людей по имени
- Сообщения шифруются на устройстве — в базе только шифртекст
- **Шифрованная геопозиция**: координаты шифруются внутри сообщения
- **Псевдонимы**: в чатах показывается никнейм, а не настоящее имя; email не виден
- Онлайн-статус и индикатор «печатает…»
- Удаление своих сообщений, отметки непрочитанного
- Светлая / тёмная / системная тема, адаптив (телефон / компьютер)
- Админ-панель владельца: расшифровка и выгрузка любой переписки в файл

## Модель шифрования (escrow — доступ владельца)

Это **не** сквозное шифрование уровня Signal, а осознанный компромисс:
содержимое защищено от посторонних, но владелец может расшифровать переписку
(например, для законного запроса).

- Каждое сообщение шифруется AES-256-GCM ключом чата. В базу идёт шифртекст.
- Ключ чата заворачивается RSA-OAEP 2048 на публичные ключи участников и на
  **escrow-ключ владельца**.
- Личные ключи участников и приватный escrow-ключ владельца лежат в приватных
  разделах базы (`data/users/<id>/…`), недоступных другим, и синхронизируются
  между устройствами одного аккаунта.
- Геопозиция (`{lat,lng,label}`) шифруется так же, как текст.

## Защита от подмены и взлома

- `escrow/pub` пишет **только владелец** (`write:"owner"`) — редактор не может
  подменить escrow-ключ и перехватить будущие чаты. Проверено.
- `pubkeys/{uid}` пишет только сам пользователь (`{self}`) — нельзя подменить
  чужой публичный ключ (защита от MITM на уровне платформы).
- Весь UI строится через `textContent` — защита от XSS; имена, координаты и
  тексты никогда не вставляются как HTML.
- Ссылки на карту строятся только из проверенных числовых координат.
- Лимит длины сообщения, защита от переполнения блоков.

### Что защищено, а что нет (честно)

| Что | Статус |
|---|---|
| Содержимое сообщений и координаты | Зашифровано. Недоступно в сырой базе и read-only зрителям. |
| Метаданные (кто с кем, когда) | Видны подписанным участникам организации. |
| Доступ владельца | Через escrow-ключ расшифровывает любой чат. |
| Целостность | Содержимое нельзя подделать или прочесть без ключа; но участник может мешать (удалять свои). |
| Предел стойкости | Ключи в базе платформы claude.ai. Для уровня «свой сервер» нужен отдельный бэкенд. |

## Про отдельное Android-приложение (APK)

Это приложение — **веб-страница в среде claude.ai**. Весь бэкенд (база,
вход, онлайн, шифрование ключей) даёт платформа через `window.claude`. Вне
claude.ai этого API нет, поэтому страницу **нельзя просто завернуть в APK** —
в отдельном приложении не будет ни базы, ни авторизации.

Настоящий APK-мессенджер — отдельный проект:

1. **Свой бэкенд**: сервер + база (например PostgreSQL) + WebSocket/push.
2. **Клиент**: тот же UI переносится на React Native / Flutter или в веб +
   Capacitor/TWA, обращаясь уже к вашему серверу, а не к `window.claude`.
3. **Сборка и подпись** APK (Android SDK, Gradle, keystore), публикация.

Крипто-слой (RSA-OAEP + AES-GCM + escrow) из этого проекта переносится в такой
клиент почти без изменений.

## Как подключить людей

- Поделитесь приложением (меню **Share**) → пригласите человека
  **по email как редактора**, тогда он сможет писать.
- По публичной ссылке зритель получает только чтение и не имеет ключей.
- Новый участник при первом входе автоматически публикует свой публичный ключ;
  ключ от чата ему выдаёт любой участник с доступом при следующем открытии.

## Технически

Один файл `index.html`. Среда артефактов claude.ai: `db` (чаты, блоки,
`pubkeys`, `handles`, `escrow`, приватные `data/users/{id}/…`), `user`
(профили, поиск), `room` (онлайн, «печатает…»), `downloads` (выгрузка).
Крипто — Web Crypto API. Код выполняется в браузере зрителя, поэтому перед
реальным использованием протестируйте переписку между двумя аккаунтами.
