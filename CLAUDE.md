# Память проекта: Aurora VPN (бот в `vpn-bot/`)

Этот файл — передача контекста между сессиями Claude. Прочитай его целиком перед работой.
Секретов здесь нет и быть не должно: репозиторий публичный (установщик качается с raw.githubusercontent.com).

## Кто и как общается
- Пользователь пишет по-русски, коротко и разговорно, иногда с матом. Отвечай по-русски, просто, без жаргона. «БС» = белые списки (мобильный интернет пускает только разрешённые адреса).
- Сервер настраивает с Android через Termius, VPN-клиент — **Happ** (на ядре Xray). Иногда v2rayNG.
- Хочет «лишь бы работало», решения часто оставляет мне («сам решай»). Новый сервер покупать **не хочет**.
- Своего файрвола в панели хостинга нет (только ufw на сервере, установщик открывает порты сам).

## Ветки и как ставить на сервер
- Рабочая ветка: **`claude/claude-md-review-rqdps8`** (продолжение `claude/claude-md-mkcp-tf0c20` ← `ccr-223727eb-c9ji1c`, в ней вся прошлая работа). Сессия может получить другую ветку — тогда бери за основу самую свежую из них (`git fetch`, сравни `git log` веток).
- **Автообновление само следует за новой веткой.** `aurora-update` берёт все ветки репозитория и выбирает самую свежую из тех, в истории которых есть установленный коммит (ветка-продолжение), записывает её в `AURORA_BRANCH`. Значит, новая сессия, начатая от этой работы, может пушить в свою ветку — сервер перейдёт на неё сам. Чужие/старые ветки (майнер, termux, `claude/android-usage-ql87m8`) не подходят — в них нет текущего коммита. **Условие: новая ветка должна начинаться от последнего коммита этой работы** (`git fetch` и бери за основу `claude/claude-md-review-rqdps8` или самую свежую ветку-продолжение). `AUTO_BRANCH=0` в `.env` — держаться одной ветки. `aurora-update check` печатает «коммит ветка», если есть обновление (им пользуется `/update`).
- Ветка по умолчанию — `claude/android-usage-ql87m8`: там работал другой ИИ. Его 6 коммитов **уже слиты** в рабочую ветку (за основу взята его версия). PR в основную ветку не открывали — пользователь не просил.
- Команда обновления сервера (всегда со ссылкой на **конкретный коммит**, иначе raw.githubusercontent отдаёт старую версию из кэша, и с `BRANCH=`, иначе установщик клонирует основную ветку):
  ```bash
  XRAY=0 BRANCH=claude/claude-md-mkcp-tf0c20 bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/<SHA>/vpn-bot/install.sh)
  ```
- **Автообновление**: установщик ставит `/usr/local/bin/aurora-update` + `aurora-update.timer` (раз в 10 минут): `git fetch` ветки из `AURORA_BRANCH` в `.env`, при новом коммите — `AURORA_AUTO=1 install.sh` (вопросы `ask` отвечаются по умолчанию). Если изменения только вне `vpn-bot/` (приложение, заметки), сервер тихо подтягивает код без переустановки; бот пишет админам «Сервер обновился сам» только при изменении `vpn-bot/` (`announce_update` + `bot_code_changed`, файл `.running_version`), `/update` — запустить сразу. **После того как пользователь один раз поставит эту версию, команды для Termius больше не нужны: достаточно запушить в ветку.** `AUTO_UPDATE=0` — выключить.
- Установщик после скачивания кода перезапускает сам себя из свежей копии (`AURORA_REEXEC`).
- `XRAY=0/1` в начале команды выключает/включает Xray. Внутри установщика имя `XRAY` занято путём к бинарнику, поэтому выбор хранится в `XRAY_WANT` (была ошибка: `XRAY=1` игнорировался — исправлено).
- Диагностика: `bash <(curl -fsSL .../vpn-bot/diag.sh)` и `... diag.sh watch`.

## Что выяснили про сеть (важно)
- Сервер пользователя — Польша (Гданьск), сеть **AS213459 Snowd Security OU**, порт 10 Гбит/с (со слов пользователя).
- `diag.sh` показал: сервер исправен, Xray/Reality работает «изнутри». Но **оператор пользователя режет TCP до адреса нашего сервера** (Reality, XHTTP, TLS — ничего по TCP не проходит, пинг не идёт). **UDP проходит** — Hysteria2 работает.
- У конкурента (Reality/TLS по TCP работает, пинг в 2–3 раза ниже) серверы на **Cherry Servers (Стокгольм)** и **OVH (Франкфурт)**. Вывод: режут конкретные адреса/подсети, а не протоколы и не целые хостинги. Пинг выше из-за маршрута до Snowd. Реально помогли бы новый IP у того же хостинга или другой хостинг — пользователь не хочет менять сервер.
- **Happ на мобильном интернете молчит, v2rayNG работает** (наблюдение пользователя). Причина по исходникам: с Xray v26.9.9 клиент Hysteria по умолчанию маскирует QUIC под Chrome (`ChromeParrot`, отключается `quicParams.disableChromeParrot`). В v2rayNG ядро свежее, у Happ — старее, его QUIC оператор узнаёт. Исправить это со стороны сервера нельзя: либо Happ обновит ядро, либо гость ставит наше приложение (ядро из `android/UPSTREAM`).
- **Белые списки на мобильном** (замеры пользователя): v2rayNG «Польша» — 0; Aurora с BBR ~1.6 Мбит/с; Brutal с потолком 30→30, 50→51, 100→92 Мбит/с. По просьбе пользователя потолок Brutal — 150 Мбит/с во всех подключениях Aurora (см. ниже). Если не поможет, надёжный путь при белых списках — мост на российском хостинге из белого списка (`/addbridge`, мост пересылает и UDP 443).
- Цифра «Проверка пинга» в Happ у Hysteria завышена (в неё входит рукопожатие QUIC), сравнивать с Reality некорректно.

## Что сейчас включено (состояние на конец прошлой сессии)
- **Xray выключен** (`XRAY_ENABLED=0`): Reality без пинга, пользователь попросил убрать. Подписка по HTTPS при этом на 443/tcp (бот), иначе на 2053.
- **Hysteria2** — основной способ. Одна Hysteria на страну, без приписок в названии при выключенном Xray («🇵🇱 Польша»). Второй вариант с обфускацией выключен (`HY2_OBFS_ON=1` — включить).
- **Hysteria для стран через прокси**: у каждой страны свой сервер `aurora-hy2@loc-КОД` на UDP 30000–30049, бот пишет конфиги в `/etc/aurora/hy2-loc-*.yaml`.
- **JSON-конфиги для Happ/v2rayNG** (`client_config.py`): в карточке только название страны, адрес/пароль внутри. Российские сайты напрямую, DNS через HTTPS, реклама режется. Первым идёт **«🚀 Лучший сервер»** — только если подключений больше одного (observatory + balancer `leastPing`). Кнопка в `/admin` выключает JSON; `?format=links` — ссылки одному гостю. В Happ это **подтверждено работает**.
- **Сайт маскировки Hysteria** меняется раз в сутки (`HY2_SNI_EVERY`), сервер Hysteria с `sniGuard: disable`, поэтому старые ссылки работают. Сообщения о смене — **только админам**, гостям ничего не шлём (так просил пользователь).
- **Купленные прокси**: команда `/webshare` (ссылка или вставленный список `host:port:логин:пароль`). Бот сам определяет страну по реальному выходу, держит самый быстрый + 2 запасных. У пользователя бесплатный тариф Webshare на 10 прокси (`p.webshare.io:80`, backbone).
- **Webshare-страны больше не удаляются с одной проверки** (пользователь: «он стёр мои прокси»): `webshare_refresh` (через 200 с после каждого запуска бота и раз в 3 ч) удалял страну, если она не ответила в эту проверку. Теперь прячет (`down`, `missing_since`), возвращает сама, удаляет только через `WEBSHARE_DROP` = 7 дней. Вернуть сразу: `/webshare now`.
- **Бесплатные авто-прокси** (`/autoproxy`): источники proxifly, proxyscrape, geonode, monosans (в списках тысячи адресов, 100+ стран). Пользователь просил оставить только хорошие страны. Жаловался «кроме Финляндии ничего нет» — причина была в переборе: лимит 60 проверок за цикл съедали одни и те же первые страны очереди. Исправлено (12.11): лимит 150, очередь стран сдвигается каждый цикл (`rot`), 4 страны ищутся одновременно, рабочий прокси «не из своей страны» запоминается для настоящей страны (`spare`, `pick_working(strays=)`). Ждём, сколько стран появится. Ещё: «после каждого update вырубает их» — бот при перезапуске терял репутацию прокси и прятал страну с первой неудачной проверки; теперь `rep/bad/spare/misses/rot` хранятся в `auto_cache.json` рядом с `vpn.json`, страна прячется только после 2 неудачных проверок подряд (`MISSES_TO_HIDE`).
- **Своё приложение Aurora VPN (Android)** — папка `android/`: `customize.py` правит исходники v2rayNG (коммит и версия ядра в `android/UPSTREAM`), `build.sh` собирает, `.github/workflows/android.yml` выкладывает APK в Releases (тег `v1.0.<номер запуска>`). Пакет `io.github.saske356.aurora`, ссылка `aurora://install-sub`. Бот: `android_app.py` качает APK из Releases, кнопка «📥 Скачать приложение» в инструкции для Android, `/app`, в подписке «⚡ Открыть в приложении» → страница `<адрес подписки>/app`. Своему приложению (User-Agent `AuroraVPN/…`) бот отдаёт JSON с `finalmask.quicParams` (keepalive 10 с — в Xray у клиента Hysteria он по умолчанию выключен). Happ получает прежнюю подписку без изменений (пользователь просил оставить). В приложении скрыты «Поделиться»/QR/редактирование/«Экспорт всего»/резервная копия (`mask_servers`), тема чёрно-золотая и тёмная по умолчанию (`brand_theme`, цвета обоев выключены). Подписка отдаёт `support-url`/`profile-web-page-url` = ссылка на бота. Обновление подписки v2rayNG сам ведёт сначала через туннель, потом напрямую. **В песочнице Claude собирать APK нельзя** (запуск gradle/чужого кода запрещён) — только CI; правки проверяй запуском `customize.py` на клоне v2rayNG.
- **Aurora (UA `AuroraVPN/…`)**: во всех Hysteria-подключениях Brutal 150/20 Мбит/с (`client_config.TURBO_QUIC`, просьба пользователя; при белых списках BBR давал 1.6 Мбит/с). Пункты «· белые списки» (Brutal 10) и «· эконом» (BBR) **убраны** — пользователь сказал, что они ничего не дают; маршрутизация `AsIs` (без DNS-запроса на каждый сайт — при белых списках он висел). Приложение с «(enc1)» в UA получает подписку зашифрованной: `aurora1:` + base64(nonce+AES-256-GCM), ключ SHA-256(`SUB_SECRET` + путь ссылки); тот же ключ в `android/customize.py` (`AuroraCrypto.kt`), тест сверяет. Это маскировка (код открыт), а не секрет. Ссылка подписки, открытая в браузере (`client_config.is_browser`), показывает страницу «Открыть в приложении», а не ключи; `?format=links` — ключи явно. Happ/v2rayNG получают прежнее.
- **Подсчёт устройств для Hysteria** (`XrayProvider.online`): раньше считались подключения, и один телефон с «Лучшим сервером» давал «9 устройств». Теперь — разные сети (`device_net`: /24 IPv4, /56 IPv6) из входов через Hysteria за последние 10 минут (`HY2_NET_WINDOW`, адрес берётся в `_hy2_auth`), не больше числа подключений; подключение без известного адреса = 1 устройство.
- Из моей части: лимит устройств (`devices.py`), трафик, скидки и возврат ушедших, воронка `/funnel`, `/traffic`, фоновая рассылка, шифрованные копии (`BACKUP_PASSWORD`, rclone), CI в `.github/workflows/tests.yml`.

## Что пробовали и убрали (не предлагать заново без запроса)
- **mKCP** (VLESS over mKCP, UDP 4443, служба `aurora-kcp`) — пользователь попросил убрать. На сервере работал, в v2rayNG пинг был, а в Happ всегда «н/д», и из-за него в Happ пропадал «Лучший сервер». Убирание `kcpSettings.seed` (в Xray с 31.01.2026 это «удалённая функция») не помогло. Установщик теперь выключает службу, удаляет `kcp.json`, закрывает порт и чистит `KCP_*` в `.env`.
- WireGuard и AmneziaWG (кнопки в /admin, подписка `/wg` для Happ) — пользователь попросил убрать; установщик выключает `wg-quick@wg0` и `awg-quick@awg0`. AmneziaWG в Happ не работает (у Xray WireGuard нет параметров Amnezia).
- XHTTP — не проходил, выключен по умолчанию.
- Источники прокси echolink.org (это EchoLink для радиолюбителей) и giamping.com (статистика чужих серверов) — не подходят.
- 3x-ui, Marzban, sing-box на сервере — не помогут: это те же TCP-протоколы.

## Где остановились (сессия 12.11.2026, вторая)
- Пользователь: «эконом и списки убери, они ничего не делают, потолок 150 у всех» — сделано. **Покупает дешёвый сервер в РФ под мост** для белых списков.
- Мост при выключенном Xray (`XRAY_ENABLED=0`) раньше не заработал бы: подбор сайта требовал `xray -test`, проверка моста шла по TCP на 8444 (там никто не слушает), проверка сайта мостов пропускалась. Исправлено: без Xray сайт подбирается только по `masking.ranked`, `check_bridges` ничего не делает, `bridge_site_job` идёт всегда. Мост пересылает UDP 443 на Hysteria основного сервера (`sniGuard: disable`, SNI = российский сайт).
- Шаги для пользователя: на сервере в РФ `bash <(curl -fsSL https://raw.githubusercontent.com/Saske356/Saske356/<SHA>/vpn-bot/install.sh) bridge` (спросит IP основного, предупреждение про TCP 8444 при Xray off — норма), затем в боте `/addbridge ru1 🇷🇺 Обход | IP | ru`. Ждём, заработает ли на мобильном при БС.
- Через мост идут и страны: установщик моста пересылает UDP 443 и порты стран (спрашивает диапазон, по умолчанию 30000–30049) на основной сервер, в подписке пункты «🇩🇪 Германия · 🇷🇺 Обход» (`hy2_entries`). Пользователь купил сервер в РФ, ждёт его установки хостингом.
- Страны идут телефон → польский сервер → прокси Webshare (бесплатные, медленные): турбо ускоряет только первый участок.
- **Новый главный экран приложения** (`android/kt/AuroraConnect.kt`, подключается `connect_screen` в `customize.py` вместо `MainBottomBar`): большая золотая кнопка с волнами, «Не подключено / Подключение… / Защищено», таймер (время начала в MMKV `aurora_connected_since`), плашка выбранной страны с пингом, заголовок «Aurora VPN». Плюс `auto_update_subscription`: подписка сама обновляется раз в 3 часа (и старым подпискам включается при запуске). Kotlin здесь не компилируется — проверка только сборкой в CI (Actions → Android app).
- Панель приложения перенесена **вверх** (пользователь: «снизу по центру неудобно»), список стран под ней. Пока VPN включён, каждые 15 с меряется настоящая задержка через туннель (`MainAction.TestCurrentServer`, результат из `uiState.status`), «нет связи» красным. Под кнопкой: «Подписка до … · N устройств» (из заголовков подписки: `subscription-userinfo` expire и `profile-title` = «Aurora VPN · N устройств») и кнопка «Продлить · устройства» → `t.me/<бот>?start=renew`. Подписка обновляется раз в час.
- **Докупка устройств в боте**: в карточке подписки «➕ Добавить устройства» (`up:`/`upd:`), доплата = разница цены месячного тарифа за оставшиеся дни (`upgrade_price`), счёт `v2:u:up<было>:0:<звёзды>:<стало>:<sub>:-`, платёж kind `upgrade`; возврат возвращает прежнее число устройств. С автопродлением нельзя (списание осталось бы по старой цене). `/start renew` открывает подписку.
- Защита от копирования: v2rayNG под GPL-3.0, исходники приложения обязаны быть открыты; объяснено пользователю, что ценность — в сервере/боте, а не в коде приложения. Подписка уже шифруется, ключи скрыты.
- Идеи на потом: авто-выбор режима, iOS (нужен платный аккаунт Apple).

## Как работать с кодом
- Тесты: `python3 -m venv /tmp/venv && /tmp/venv/bin/pip install -r vpn-bot/requirements.txt`, затем из `vpn-bot/`: `/tmp/venv/bin/python -m unittest discover -s tests`. Без библиотек бота сквозной тест `test_bot_flows` пропускается молча — ставь зависимости.
- В тестах вместо xray/hysteria/systemctl/wg — заглушки (shell/python-скрипты в temp). В сеть тесты не ходят.
- В песочнице Claude **нельзя запускать скачанные бинарники** (xray, hysteria) — форматы сверяй по исходникам (sparse-clone XTLS/Xray-core, apernet/hysteria).
- В песочнице исходящие подключения подменяются: `curl --proxy` через чужой прокси показывает адрес самой песочницы — проверка прокси отсюда недостоверна.
- Xray определяет формат конфига по расширению: временные файлы для `xray run -test` должны кончаться на `.json` (была ошибка с `kcp.json.tmp`). В тестах заглушки Xray тоже отвергают файлы без `.json`.
- Перед коммитом: `pyflakes`, `bash -n` для `*.sh`, все тесты.
- Ключевые файлы: `bot.py` (бот), `xray_provider.py` (Xray, Hysteria, страны, подписка, страница /app), `client_config.py` (JSON для Happ), `install.sh`, `diag.sh`, `webshare.py`, `devices.py`, `android_app.py`, `android/customize.py`, `auto_proxy.py`, `proxy_relay.py`, `public_proxies.py`, `db.py`.
